PROPÓSITO INSTITUCIONAL DO APP:
O app existe pra ser arquivo de defesa profissional. Cada decisão de design
ja foi filtrada por: "Se um gestor questionar o trabalho do condutor 6 meses
depois, esse registro defende ele?". Implementar mantendo esse norte.

PRINCÍPIOS NORTEADORES (consultar em cada decisão técnica):
1. Forma segue função — cortar decoração que não serve à prestação de contas
2. Defesa profissional — todo campo/foto/GPS/timestamp serve à auditoria
3. Tom institucional sério — sem RPG, militar gamer, ingles decorativo
4. Subtração no MVP — quando em dúvida, tira
5. Auditor é usuário invisível — toda tela vai virar PDF

OBJETIVO: Definir estrutura de dados completa antes de implementar features.
Modelos pensados pra auditoria, sincronização offline, e crescimento.

ENTREGÁVEIS - COLEÇÕES FIRESTORE:

1. /users
   - uid (auth)
   - ra (matricula GCM, ex: "691755")
   - name (nome completo)
   - role ('condutor' | 'gestor')
   - avatar_url
   - active_dog_id (cão ativo no momento)
   - active_shift_id (turno ativo)
   - created_at, updated_at

2. /dogs
   - id
   - name (ex: "Bono")
   - breed (ex: "Malinois")
   - sex ('macho' | 'femea')
   - birth_date
   - weight_current (kg)
   - operational_since (data que virou operacional, se aplicável)
   - status ('active' | 'inactive' | 'retired' | 'donated')
   - primary_handler_id (uid do condutor titular)
   - photo_url
   - created_at, updated_at

3. /dogs/{dogId}/weight_history
   - id
   - weight_kg
   - measured_at
   - measured_by (uid)
   - photo_url (foto da balança, se houver)
   - notes

4. /dogs/{dogId}/specialties
   - id
   - type ('guarda_protecao' | 'busca_captura' | 'deteccao' | 'obediencia' | 'condicionamento')
   - status ('not_started' | 'in_formation' | 'operational')
   - started_at, completed_at (se aplicável)
   - current_phase (ref para fase atual, varia por especialidade)
   - notes

5. /dogs/{dogId}/commands (biblioteca de comandos por cão)
   - id
   - name (ex: "Senta")
   - category ('operacional' | 'posicional' | 'postural' | 'habilidade')
   - stage ('not_trained' | 'introduced' | 'developing' | 'consolidated' | 'operational')
   - learned_at, mastered_at
   - notes

6. /dogs/{dogId}/health_events
   - id
   - type ('vaccine' | 'antipulgas' | 'vermifuge' | 'exam' | 'consultation' | 'medication' | 'injury' | 'symptom')
   - subtype (ex: 'V10', 'Bravecto', 'hemograma')
   - applied_at
   - applied_by (uid)
   - veterinarian (nome + CRMV)
   - product_brand, product_lot
   - next_due_date (calculado ou inserido)
   - pdf_attachment_url
   - notes
   - audit_trail (array de edições)

7. /dogs/{dogId}/documents (laudos, certificações, honras)
   - id
   - type ('laudo' | 'certificacao' | 'curso' | 'honraria' | 'cadastro_institucional')
   - title (ex: "Laudo nutricional")
   - issuer_name (ex: "Dra. Ana Souza")
   - issuer_credentials (ex: "CRMV 12345")
   - issuer_institution
   - issued_at
   - file_url (PDF)
   - notes

8. /dogs/{dogId}/training_sessions
   - id
   - specialty_type
   - session_subtype ('formacao' | 'manutencao' | 'avaliacao')
   - phase_or_module (ex: "M2" pra B&C, "F3" pra Detecção)
   - figurante_id (uid)
   - orientador_id (uid, se aplicável)
   - equipment_used (array)
   - capabilities_worked (array)
   - commands_worked (array)
   - environment (ex: 'mata_fechada', 'urbano', 'canil')
   - duration_minutes
   - distance_meters (se com GPS)
   - gps_track_id (ref se houver)
   - result_classification (B&C: 'completa' | 'checagem' | 'perda_rastro'; Detecção: array de attempts)
   - evaluation (multi-critério)
   - payment_type (Guarda: 'caca' | 'defesa' | 'agressao' | 'sem')
   - scenario_simulated (bool)
   - scenario_description
   - dog_behavior
   - observations
   - photos (array de urls)
   - created_at, created_by
   - audit_trail

9. /dogs/{dogId}/training_attempts (sessões de Detecção - granular)
   - id
   - session_id (ref)
   - attempt_number
   - box_position ('left' | 'center' | 'right')
   - result ('hit' | 'miss')
   - miss_type ('went_empty' | 'didnt_sit' | 'hesitated' | 'other')
   - timestamp
   - notes

10. /dogs/{dogId}/detection_lines (linhas de detecção)
    - id (ex: 'drugs', 'weapons', 'cadaver')
    - status ('not_started' | 'in_formation' | 'operational')
    - current_phase ('triagem' | 'fase_1' | 'fase_2' | 'fase_3' | 'fase_4' | 'fase_5')
    - consecutive_hits (contador atual)
    - best_streak (melhor sequência histórica)
    - imprinting_material (ex: 'Nose-MP Drogas')
    - external_certification (ref se houver)

11. /dogs/{dogId}/external_certifications
    - id
    - line_type (drugs/weapons/cadaver)
    - certification_date
    - evaluator_name
    - evaluator_institution
    - location
    - result ('approved' | 'rejected')
    - certificate_url
    - observations

12. /occurrences
    - id
    - dog_id (ref)
    - primary_handler_id (uid)
    - team_handlers (array de uids)
    - nature ('faro_veiculo' | 'faro_entorpecente' | 'busca_mata' | 'apoio_mandado' | etc)
    - started_at, ended_at (null se em andamento)
    - duration_minutes
    - status ('in_progress' | 'finalized' | 'cancelled')
    - location_start (gps + endereço)
    - location_end (se diferente)
    - final_report (texto livre)
    - audio_narration_url
    - result_type (array: 'droga_apreendida' | 'arma_apreendida' | 'individuo_detido' | 'bo_elaborado' | 'apoio_prestado' | 'encaminhamento' | 'sem_ocorrencia')
    - result_details (objeto com info específica por tipo)
    - pdf_export_url
    - audit_trail

13. /occurrences/{occId}/events (eventos dentro da ocorrência)
    - id
    - timestamp
    - type ('inicio' | 'abordagem' | 'busca_cao' | 'indicacao' | 'material' | 'bo' | 'medico' | 'encerramento' | 'observacao' | 'foto')
    - title
    - description
    - location_gps
    - photo_urls (array)
    - registered_by (uid)
    - audit_trail (edições subsequentes)

14. /dogs/{dogId}/routine_events
    - id
    - type ('alimentacao' | 'passeio' | 'brincadeira' | 'limpeza' | 'escovacao' | 'banho')
    - subtype (manhã/tarde/noite pra alimentação)
    - quantity (com unidade pra alimentação)
    - duration_minutes (pra passeios)
    - timestamp
    - registered_by (uid)
    - photo_url
    - notes
    - audit_trail

15. /shifts
    - id
    - handler_id (uid)
    - dog_id (ref)
    - started_at, ended_at
    - status ('active' | 'finalized')
    - location_start
    - notes

16. /gps_tracks
    - id
    - session_id ou occurrence_id (parent)
    - started_at, ended_at
    - points (array de {lat, lng, timestamp, accuracy})
    - distance_meters
    - duration_seconds
    - average_speed
    - markers (array de eventos marcados)

17. /audit_logs (trilha de auditoria centralizada)
    - id
    - entity_type ('occurrence' | 'event' | 'training' | 'health' | etc)
    - entity_id
    - action ('created' | 'updated' | 'deleted')
    - field_name (se update)
    - old_value, new_value
    - reason (obrigatório em delete)
    - performed_by (uid)
    - performed_at
    - ip_address (opcional)

REGRAS DE SEGURANÇA (FIRESTORE RULES):
- Condutor só lê/escreve nos cães que ele conduz ou tem permissão
- Gestor lê tudo, escreve restrito
- Audit_logs nunca podem ser editados após criação
- Soft delete: status muda mas registro nunca some
- Timestamps de criação são imutáveis

CRITÉRIO DE PRONTO:
- Models Dart implementados pra todas as coleções
- Repositories implementados com CRUD básico
- Seed data populado pra dev (Bono + Apolo + alguns eventos)
- Regras de segurança testadas

================================================================================
PERGUNTAS FREQUENTES
================================================================================

P: E se o Claude Code propor "Material Design"?
R: Negue. Use o design system custom dos mockups. Material 3 pode contaminar
   o tom institucional sério.

P: Devo usar Firestore ou Realtime DB?
R: Firestore. Melhor pra queries complexas, offline mode robusto.

P: Como lidar com fotos pesadas?
R: Comprimir client-side (max 2048px). Subir thumbnail separado. EXIF
   preservado com package: image.

P: PDFs assinados digitalmente?
R: MVP: hash SHA-256 + timestamp. Futuro: integração com certificado A3
   ou ICP-Brasil.

P: Múltiplos cães por condutor — como tratar?
R: Cada cão é mundo separado. Trocar cão = reset do contexto.
   Não misturar dados.

P: Gestor consegue ver todos os cães?
R: Sim, com role 'gestor'. Mas é leitura. Edição continua só do condutor titular.
