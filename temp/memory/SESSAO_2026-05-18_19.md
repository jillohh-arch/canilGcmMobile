## Fase 7 — Correção de Crash (commit 10)

### Problema
Tela cinza (crash) ao abrir `StartOccurrenceScreen`.

### Causa raiz
Código usava `.cast<dynamic>().firstWhere(...)` seguido de `dog?.photoUrl as String?`. O modelo `Dog` não tem campo `photoUrl` — o campo correto é `profileImageUrl`. O `.cast<dynamic>()` escondia o erro em compile-time, manifestando como `NoSuchMethodError` em runtime.

### Correção
- Substituído `.cast<dynamic>().firstWhere(...)` por `.where((d) => d.id == dogId)` tipado
- Substituído `dog?.photoUrl` por `dog?.profileImageUrl`
- Adicionado try/catch em `_loadNatures()` com fallback para `OccurrenceNatureSeed.items`

## Fase 8 — Correções de UX (commit 11)

### Issue 1: UUIDs no lugar de nomes
**Problema**: `ActiveOccurrenceContextCard` recebia `occ?.dogId` (UUID) e `occ?.primaryHandlerId` (Firebase UID) como texto exibido.

**Correção**: 
- Adicionado `context.watch<DogViewModel>()`, `AuthViewModel`, `UserViewModel` no build
- Resolve `dogId` → nome via `dogVM.dogs.where((d) => d.id == dogId).first.name`
- Resolve handler → nome via `HandlerIdentityService.raFromUser()` + `userVM.displayNameFor()`

### Issue 2: Fotos nos avatares
**Problema**: `_MiniAvatar` só mostrava iniciais de texto.

**Correção**:
- `ActiveOccurrenceContextCard` agora aceita `dogImageUrl` e `handlerImageUrl`
- `_MiniAvatar` renderiza `Image.network` quando URL disponível, fallback para iniciais
- Mesma correção aplicada na Tela 2.1 (`StartOccurrenceBinomio` com `handlerImageUrl`)

### Issue 3: Timeline não populando
**Status**: Deixado para implementação futura (decisão do usuário).

### Issue 4: Grid rápido sem ação visível
**Problema**: `_addQuickEvent` era async e falhava silenciosamente (GPS timeout ou erro Firestore).

**Correção**:
- SnackBar imediato "Registrando: {título}..." ao tocar
- SnackBar verde "✓ {título} registrado" após sucesso
- SnackBar vermelho com mensagem de erro em caso de falha
- GPS continua opcional (não bloqueia criação do evento)

### Foto do condutor na Tela 2.1
**Problema**: `displayNameFor` era chamado com `ra: ''` (nunca encontrava o user). Avatar do condutor recebia `imageUrl: null`.

**Correção**:
- Extrai RA via `HandlerIdentityService.raFromUser(authVM.user)`
- Busca `UserModel` via `userVM.findByRa(handlerRa)`
- Passa `handlerUser?.photoUrl ?? authVM.user?.photoURL` como foto

## Decisões Técnicas

1. **Módulo separado de `/incidents`**: Zero modificações no código legado. Coexistência pacífica.
2. **GPS por evento**: Cada registro rápido captura coordenadas independentes (não só da ocorrência).
3. **GPS não-bloqueante**: Se falhar, o evento é criado sem coordenadas.
4. **Stream reativa**: `watchEvents` mantém a UI sincronizada com Firestore em tempo real.
5. **Soft-delete**: Nenhum documento é removido fisicamente — apenas marcado.
6. **Hash de integridade**: Preparado para Tela 2.4 (finalização com SHA-256).
7. **Feedback háptico**: Diferenciado por ação (light = navegação, medium = criação).
